- **A query that leaves out its primary key no longer shows a phantom `Id` column full of NULLs.**
  `SELECT Col1, Col2 FROM Tab1` (SQL Server and Postgres) got an extra, unrequested primary-key column
  in the result grid, every row NULL. `CommandBehavior.KeyInfo` — needed so the grid knows which rows are
  editable — makes the driver append that column purely as key-resolution metadata; the provider counted
  it as a normal selected column instead of skipping it.
