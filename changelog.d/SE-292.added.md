- **You choose where DataTray keeps your connection passwords.** Onboarding has a third step, between
  picking an engine and adding your first connection: the system vault your OS already runs (macOS
  Keychain, Windows Credential Manager, Linux Secret Service) or an encrypted file in your DataTray
  profile. Both options say who holds the key, who else can reach it and what you lose if it goes wrong,
  so the choice is made on the trade-off rather than on which sounded safer.
- **The encrypted file store works where there is no keychain at all.** A headless or locked-down Linux
  box has no Secret Service, and until now that meant DataTray could not save a password there at all —
  it fell over at startup. That machine now gets the file store, with the vault option greyed out and the
  reason spelled out. The file is AES-256-GCM under a master password you set in the same step; DataTray
  never writes a secret into it without one.
- **Preferences ▸ Security says which store you are on.** And with the file store active, "Disable" for
  the master password is gone — the store cannot work without it — replaced by the sentence that says so.
  Existing installations are on the system vault, exactly as before, and nothing moves on its own.
