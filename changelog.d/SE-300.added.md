- **Long queries show what the server is saying, while it says it.** A query tab gets a **Messages** tab
  next to its results as soon as a run has something to report: `PRINT` and `RAISERROR` (also
  `WITH NOWAIT`, line by line as the script runs) and `(n rows affected)` per statement on SQL Server,
  `NOTICE`/`WARNING` on PostgreSQL, and warnings on MySQL. Every line has its time; warnings and errors
  are marked and counted, and an error that stops the run sits in the same timeline as the messages
  before it. Filter by text or level, copy the selection or what is shown, clear it, and the list follows
  the newest line until you scroll up. It keeps the latest 10,000 lines and says when older ones were
  dropped. While a query runs, Run becomes Stop with a ticking clock beside it, and the status bar shows
  the latest message; afterwards it says whether the run completed, was cancelled or failed, and where.
  Messages are cleared when the next run starts, or kept behind a divider with
  *Settings › Query › Keep messages between runs*. Engines without messages show only the clock.
